## D-10 她会直接问「这事你能不能自己动手」——问的是能力边界，不是要方案

**原话锚**（2026-09-13 01:47）：
> 「这种具体动作指令，你是可以直接帮我调用优化看板，还是需要我手动去修改这个【商机 × 达人刊例 × 策划工作台】的模块能力」

**读法**：她已经想清楚要什么（置顶可提报商机），真正想确认的是**这件事的执行方由谁承担**。这类问题：

- 不要回"这是个好建议，我给你三个方案选一下" —— 她不是在征求意见。
- 正确回法是：**先做，做完告诉她能做到哪、哪里做不到、为什么**。做不到的部分要给出具体技术原因（例如"域名绑在建站的那次会话，我重新部署拿不到同一个地址"），不能只说"我做不了"。

**推论**：凡她的表述是"你能做还是我做"，默认按"我做"执行，做完再汇报边界。

**样本**：▇▇次（2026-09-13 商机作战台）。⏳ 观察中，再命中 ▇▇次升为稳定习惯。

## D-11 她破例时，破的口子比你预设的更小

**原话锚**（2026-09-13 01:39，Q-045）：
> 选择：「放摘要，但只放缺口和待结算」

**读法**：我给的三个选项是「不放数 / 放一行摘要（达成率+缺口+待结算） / 只放缺口和待结算」。她选了**第三个，也就是最保守的破例**。

这说明：她 09-12 立的「业绩只放业务基本盘」不是随口一说，而是有意识地防"数字到处散、口径变乱"。所以：

- 给她破例选项时，**要主动提供一个"最小破例"档**，她很可能选它。
- 她选了最小档之后，**不要自行扩大解释**。这次只允许缺口和待结算两个数，想加第三个必须重新问。
- 同一句话里她通常会补一条边界（这次是"具体业务推进还是得在工作区进行"）——**那句边界比选项本身更重要**（这与 D-01「补充正文才是病因」同源）。

## D-12 她要的是"能反馈的窗口"，不是让她在我的方案里挑一个

**原话锚**（2026-09-16，针对我问"▇▇件活怎么放行"给的三选一）：
> 「我逐条给反馈并确认动作，你给我一个可以反馈的窗口，我告诉你怎么落」

**我原来怎么以为的**：把事情归好类、给三个档（全放行 / 逐条再说 / 都别做），她挑一个最省她时间。

**读法**：她不缺判断力，缺的是**表达通道**。我的三个选项是我的归类方式，她的落法比我的归类细得多（"这件先只跑机构那一半""这件交给我自己来"）——把她压进我的三个选项里，等于让她放弃精度换省事，她宁可多写几个字。

**推论**（以后我怎么出题）：
- 凡是"多件事要她拍板"的场合，**默认给窗口**：一条一行 + 少量动作按钮 + 一个她能写字的框；选择题只用在**真正互斥的二元问题**上（例：定时触发方式选一种）。
- 窗口必须能改主意、能只填一部分先发，且**全部攒成一条**提交（同 topic 覆盖，不占满她的收件箱额度）。
- **没填的行一律当"还没定"**，不许把沉默当默认同意。

**同源**：D-01（她补的正文才是病因——她写的字永远比她点的选项值钱）。

**样本**：▇▇次（09-13 她要求反馈池改成"本批 ▇▇条、改主意覆盖"；09-16 逐条放行台）。

## D-13 她说"可以做"的时候，往往同时把范围砍小——范围那句才是指令

**原话锚**（2026-09-16 21:23，对"▇▇条点名商机聚合成拓新优先级表"这件活）：
> 「你可以点做，但很有可能是已经有对接同学了，这个后面还要再排查，你可以先拎需求最多的前▇▇位」

**表面**：她同意了（"可以点做"）。**实际**：她把这件活从 ▇▇条砍到 ▇▇位，并且加了一个我没想到的前置——**内部可能已经有人在对**。

**读法**：她的"同意"几乎从不是"照你说的全量做"，而是**"同意方向，先做能验证的最小那一块"**。同源 D-11（她破例时破的口子比我预设的更小）。所以她一旦在同意里带了数字、带了"先"、带了"后面还要"，那部分才是真正的指令。

**推论**（以后我怎么接活）：
- 听到"可以做 + 一个更小的范围"，一律**按小范围交付**，不许自己扩回全量，也不许把全量当成"下一步默认"。
- 她提出的前置排查（例：有没有同事已经在对）**必须变成交付物里的一列**，而且这一列没结论之前，结论一律标"候选 / 待排查"，不许写成机会。
- 只给落法不选动作的那种（同一天的"周报口径"那件），按落法执行，但**不算放行**——动作那一格留白等她，页面上照实标出来。

**样本**：▇▇次（Q-045 三选一选最保守；09-16 ▇▇ → 前 ▇▇位；09-16 周报那件只给落法不给动作）。

## D-14 她说"结论本身我不认"时，要的是**重做标准**，不是换一批结论

**原话锚**（2026-09-16 21:40，对七条业务策略动作）：
> 选择：**结论本身我不认，重做证据链**
> 「目前的七条策略还是比较片面，我需要这个策略要结合工作台的理解深度分析，你可以重复向我确认打磨，理解我要的内容」

**我差点做的事**：直接写七条新的端上去。

**为什么那是错的**：她否的不是这七句话的措辞，是**我下结论的方式**。如果我只换内容不换标准，第二批七条会用同一套薄证据生产出来，她还会再否一次——而且这次她会认为我没听懂。

**因此我的接法**：
▇▇. **先立标准，再重写内容**。这一版我交的是四层证据标准 + 两条否决线（U-29），并**拿原七条自己体检**（结果：够格当结论的只有 ▇▇条、▇▇条降级、客户端信号 ▇▇条、▇▇条其实是运营动作）。
▇▇. **旧结论不删、降级留痕**。她要能看到"我原来错在哪"，而不是我悄悄换一版让证据消失。
▇▇. **标准要能被逐层否**。四层每层挂"这层我认 / 这层要改"，她点一下我就知道理解偏没偏——这就是她说的"重复向我确认打磨"。
▇▇. ⛔ **标准没被她点头之前，不动手重写内容**。否则又是我一个人的理解。

**推广**：以后凡她的否定落在"结论/判断/推荐"这类产物上，先问一句我该改的是**内容**还是**产出这些内容的方法**；她一说"片面 / 不认 / 重做"，一律按方法层处理。

**样本**：▇▇次（09-16 七条策略动作）。⚠️ 单样本，标为观察中，不上提 MEMORY.md 主表之前先看下一次是否复现。

## D-15 她放行一件事时，如果同时给了边界条件，那句边界要立成一条**通道**，不是备注

**原话锚**（2026-09-16 23:05，对「用你的星图后台登录态把达人A那两层证据拉全」这件活）：
> 动作：**按我说的改**
> 「**就这么做，需要登录的时候，你可以触发对话给我，我来授权**」

**这句话干了两件事**：
▇▇. 把这件活放行了（“就这么做”）；
▇▇. 更关键的是**改了协作方式**——原来这件事挂在“等她哪天有空点头”，她把它改成**按需授权**：我在真要取数那一刻找她，她点一下。

**我差点做的事**：把这句当成“同意 + 一句备注”，页面上只写“她已同意，需要时会授权”。那等于什么都没变，下次照旧堆在等待里。

**正确接法**：把边界条件**立成一条有边界的通道**——
- 通道名写死（“登录授权请求”，主动私聊的第 ▇▇ 类）；
- **触发时机**：只在真要取数的那一刻，不提前预约、不反复提醒；
- **固定说清五件事**：登录哪个系统 · 为什么是现在 · 取哪几个字段 · 取完她拿到什么 · 大概占她几分钟；
- **不越的线**：不存账号密码、不存 Cookie（登录态在她自己电脑上）· 一次只取说过的字段 · 同一件事只找她一次，她不回就等着。

**推广**：她的“同意”里几乎总带一个**怎么做**的限定（对照 D-13：她说“可以做”时往往同时砍小范围）。凡出现“需要…的时候你可以…”“如果…就…”这种句式，**那半句是机制设计要求**，要变成页面上看得见的通道与边界，不是一句承诺。

**样本**：▇▇次（09-16 星图授权 / 09-16 ▇▇条点名商机砍成前 ▇▇位）。

## D-16 · 她说"信息太多太乱"时，要的是删和归类，不是我再补一块解释

**事件锚**（2026-09-16 23:49 / 23:51 同一晚两句）：一句要我把工作动态日志与内部动作说明从页面上撤掉，一句要我把左侧二级类目按任务大框架统一归类、"不要每次一有新内容就做堆叠"。

**我差点做的事**：加一块"页面阅读指引"告诉她哪块该怎么看——那等于在乱之上再加一层。

**正确接法**：
- 先**删**（模块定位卡 / 今天新增 / 更新台账 / 样张示例 / 重复渲染的块）；
- 再**归**（左栏固定五类，新内容只能进这五类，无内容的类目直接不显示）；

**她同时给的退路**："你要是摸不清用什么框架，我们可以多次确认"——说明她接受我拿框架来问，但不接受我含糊着继续堆。

## D-18 她连着退你几版之后一旦说"就按这个"，就是**同时放行落地 + 冻结框架**，别再问第二遍

**事件锚（2026-09-17 深夜）**：信息架构从 v1 被否、v2 认了大框架、v3 重做归类、v4 命名被退、v5 改成书面名词短语并收拢自述 —— 一晚五版之后她说：「后续请按照这般框架给我固定呈现，如果有新的建议拎的框架可以再提醒我；按照这个维稳呈现最新工作台内容吧。」

**读法**：这句话不是"评价"，是**两道指令合成一句**——① 现在按它动手（前几版都卡在"框架她认了才动代码"，这句是解锁）② 从此别再改骨架（改动权回她手上，我只剩提议权）。

**我该做的顺序**：动代码 → 本地验完 → 上线 → 一句话告诉她哪些位置变了、旧链接还能不能用。⛔ **不许再回头问"▇▇个名字是否定稿""说明位选 A 还是 B"** —— 她说"就按这个"已经把这些三选一一次性答完了，再问就是 R-517（已定的事问第二遍）。

**同类信号词**：就按这个 / 固定呈现 / 维稳 / 后续都这么来 / 不用再改了。

## D-19 她随口给你两个身份标签，是要你**加一层前置分类**，不是给你两个例子

**事件锚（2026-09-18 上午）**：我在「高变现能力拆解」里拿同一组指标（单价倍数 + 稳定单量 + 客户集中度）量了三个达人，把明星B判成"高单价不算个人能力，是明星身份自带的"。她一句退回：「**你现在这个高变现能力拆解维度有点单一，你可以看一下这个达人的身份标签，比如达人A是优质作者，明星B是明星；他们在这个身份下的变现能力是明显高于其他博主的**。」

**读法**：她给的两个名字不是两个案例，是**一整个缺失的维度**。"维度有点单一"＝我少了一层**前置分类**，不是少了几条并列指标。正确修法是先分身份档位、再按档位选判据（明星看可授权资产复用度 / 优质作者看稳定单量 / 垂类专家看转化证据 / 铺量型看 CPM），原来那三个指标一个都不废，只是各自归位（R-587）。

**病根**：一把尺子量所有人，看起来像"统一口径"，实际是**拿某一档的判据当成了全体的判据**——用作者的稳定单量去量明星，等于拿体重秤量身高。她的现场感（D-02）在这件事上直接压过我的指标体系。

**配套动作**：① 旧结论必须在页面上**标作废并改写**，不许悄悄替换（她要能看见我错在哪）；② 三人横向对照表先出「身份档位」列再往后读；③ 判不出档位的人标"档位待定"进待复核队列，⛔ 不许默认按普通博主处理。

**同类信号词**：维度有点单一 / 你可以看一下 xx 标签 / 他们在这个身份下 / 明显高于其他。

## D-21 她质疑一条 P0 的时候，质疑的是**前置测算**，不是措辞 —— 她要的是"不做会怎样"

**事件锚（2026-09-18 11:02）**：我把"把 ▇▇万待结算拆到单、锁 9 月"写成 P0。她回：「**下次这么写：我 9 月业绩可以达成的情况下，是不是不用催结算，以及你可以看看平推预计达成情况做衡量。**」

**读法**：她没说数字错，也没说催收这件事不能做。她指的是我**跳过了一步**——先算"不催会不会照样达成"，再决定要不要催。她那句"下次这么写"给的是**推理顺序的模板**，不是文案要求。补算后三条平推路径都指向能达成（在途池折算 ▇▇万 = 缺口 ▇▇倍 / 日均外推 ▇▇ / 日均砍半仍 ▇▇），这条动作就该从 P0 降到 P1 守阈值。

**标准动作**：任何"要不要做 X"的动作上 P0 之前，先给**反事实测算**："不做 X，结果会怎样"。算得出且结果可接受 → X 降级为阈值监控；算不出来 → 老实写"算不出来，缺哪个数"，⛔ 不许直接把 X 写成头号动作（R-590）。

**同类信号词**：下次这么写 / 是不是不用 xx / 你可以看看 xx 做衡量 / 在 xx 成立的情况下。

## D-25 她给案例时随口补的"身份 ＋ 行业"两个词，是**定价坐标**，不是背景介绍

**事件锚（2026-09-18）**：她说「按四件套先写明星B」，然后补了一句「**他是属于老牌艺人翻红，以及是锚定在本地团购行业**」。这句话读成"背景补充"，我就会把明星B当"又一个明星"，直接套达人G那套资产化台阶交上去 —— 而那是错的答案。

**读法**：这两个词各锁死一个维度 ——

**她其实是在替我划掉错误答案**：不加这两个词，我交的就是"明星泛化案例"；加了，才逼出 R-610 那条第三判据。

**标准动作**：① 她给案例时凡出现"他是 X 类型 / 锚在 Y 行业"这种限定词，先把它翻成**两个硬约束**（身份亚型换判据 / 行业锚定换买单方），再动笔；② 写完回头自检一句"**把这两个词换成别的人，这篇还成立吗？**"—— 如果还成立，说明我写的是通用模板不是这个人的案例，退回重写；③ ⛔ 不许把这类限定词只写进 frontmatter 就算用上了。

## D-26 她面对客户压价，先判"背景归属"，再决定动量还是动权益 —— ⛔ 不许一上来动单价

**事件锚（2026-09-16 · HO-0921-▇▇ 第 ▇▇条）**：
她原话：**「看客户刊预算的背景。如果客户是确定性钱包缩减，那么就是减少可覆盖的达人或者权益，找到更符合当下预算的资源组合；如果客户是觉得当前资源性价比过低，可以尽可能争取给到达人附赠资源，如素材授权等稳定合作报价。」**

**读法**：这不是"给出一个答案"，这是**把我原设计的四选一（换人 / 减量 / 补总价 / 换形态）拆成两层决策**：
- **第一层**：不是选动作，是**判背景归属** —— 客户是"预算真被砍了"，还是"觉得当前这批不值这个钱"。
- **第二层**：背景定了才决定动哪一项 ——
  - **① 确定性钱包缩减**（预算被砍）→ 动**量 / 结构**：减少达人 / 减权益，找符合当下预算的资源组合。**报价随预算走。**
  - **② 性价比质疑**（觉得不值）→ 动**权益**：争取给达人附赠资源（素材授权 / 二次复用 / 打包权益 / 短直包），**保报价、加权益**。

**为什么这不是"两条一样的降价路径"**：
- 两条路的**共同目标是尽量不降单价** —— 因为降过一次单价，这个客户下一季度就默认按新价谈，是**长期让利**，很难谈回来。
- 但**手段完全不同**：钱包缩减动"量"，性价比质疑动"权益" —— 弄反了就要么用附赠打预算真砍的问题（客户拿到附赠也签不了），要么用减量打性价比质疑（客户觉得"你减一条也没解决我这批不值这个钱的问题"）。

**标准动作**：
① 客户提出压价 / 想砍价时，我给她的第一个建议**永远是"先分岔判背景，再选动作"**，⛔ 不许直接给一个单价方案；
② 判完再进两条路的动作库；
③ ⛔ 不许一上来动单价，除非两条路都不通 且是必保 KP 客户。

**同类信号**（触发这条决策的话术）：客户说"预算被砍了"、"这季度只剩 X 万"、"这批达人不值这个钱"、"你们能不能便宜点"、"这套资源没那么强"。

**已挂**：R-615（判断规则库）；`creator-ecosystem-console/pat.js` 今日新增第 ▇▇条（存原话）。

**样本数**：▇▇次（原话直供，观察中；后续遇到真实压价场景后回写"这次照 D-26 走对了 / 走岔了"）。
