### E-01 新增规则编号撞号　`2026-09-13，当天发生并当天修`
- **错在哪**：给规则库追加 ▇▇条新规则，直接从 R-506 开始编，没查已有最大号，撞上了既有的 R-506~R-509。
- **后果**：同一个编号指两条不同规则，任何引用都会指错。已整体改为 R-524~R-527，并回改台账/日志/技能池三处引用。
- **自检**：写新规则前先 `grep -o "R-[0-9]*" _系统/判断规则库.md | sort -u | tail`，从最大号 +▇▇ 开始。

### E-02 写死的数字早晚会骗人　`2026-09-13 第七批收尾`
- **错在哪**：工作台首页把"▇▇条规则 / ▇▇篇笔记"等底数写死在多个 js 文件里，仓库长大后页面还在报旧数；
  "等你定 ▇▇件"也是写死的，和页面上实际 ▇▇个问题不一致。
- **后果**：她看到的第一屏就是错的，整页可信度归零。
- **自检**：任何出现在 UI 上的统计数，必须来自实测或实时计算；改数字要**全局搜一遍**（`grep -rn "旧值"`），不能只改一处。

### E-03 `&&` 链式命令会吞掉失败　`R-505`
- **错在哪**：用 `cmd1 && cmd2 && cmd3` 部署，中间失败了但整体看着像成功。
- **自检**：验证类命令分开跑；关键步骤单独确认返回值。

### E-04 验"没报错"不等于验"生效"　`R-506`
- **错在哪**：`node --check` 过了就当页面好了，实际渲染没出来（v8 Hero 未渲染，因为 `!window.DATA` 判断对 `const DATA` 无效）。
- **自检**：改完必须用 `html_vision` 看真实渲染结果，控制台 + 视觉双确认。

### E-05 元数据仪表盘替代不了内容本身　`R-522`
- **错在哪**：给她看"信息完善度 ▇▇"这种系统自评，而她要的是"这个模块里到底装着什么具体内容"。
- **自检**：交付前问一句——这一页有没有出现她业务里的真名字、真数字、真日期？没有就不算内容。

### E-06 后台做了但 UI 上没有 = 等于没做　`R-521`
- **错在哪**：一键交办后端已经生成交办单，但页面上没给她看到单号，等于这个功能不存在。
- **自检**：每个新能力都要问"她在哪一屏能看到它、能点它"。

## E-11 拿旧快照当常量：把 09-06 的「▇▇条商机 / A 类 ▇▇条」讲了一个星期

**发生**（2026-09-13）：她基于工作台上的数字提建议：「▇▇条里真正能提报的只有 ▇▇条」。我去读作战台真实数据文件才发现：

- 实际是 **▇▇条（开放 ▇▇）**，不是 ▇▇
- A 类实际 **▇▇条**，不是 ▇▇
- 真正能提报（A 且有真实提报表）**▇▇条**

那个站每天 10:00 自动增量同步，数据一直在涨。我在 09-06 抓了一次快照写进页面，之后**一直拿它当事实复述**，还让她基于错的数字做判断。

**性质**：这是 E-02（写死数字）的升级版，也更严重 —— E-02 是页面显示旧值，这次是**我自己的认知停留在旧值上，并把它讲给了她**。

**防复发**：

▇▇. 凡引用作战台/看板类**会自动更新**的数据源，每次引用前重新读，不许凭记忆复述。

▇▇. 页面上不写死这类数字，改为从数据文件现算；无法现算的必须显式标注截止日。

## E-13 把「数据字段缺失」当成了「业务能力具备」

**发生**（2026-09-13）：我在生态盘面写了机会①「▇▇位无刊例达人 → 效果结算池」。她一句话否掉：**「▇▇个无刊例达人 不等于 效果结算池」**。

**错在哪**：无刊例只说明**机构没把报价整理给我**（一个数据收集问题）。效果结算的前置是**达人有电商转化能力**（一个业务能力问题）。我把前者当成了后者的入口，中间跳过了"这些人到底有没有带货能力"这一步——而这一步我**根本算不出来**，因为转化证据字段还没接进数据管道。

**性质**：不是数字算错，是**推导链条里凭空插了一步**。这类错比算错危险，因为数字都对，链条不成立。

**防复发**：写"X → Y"这种转化路径前，强制自问：
▇▇. Y 的**前置能力**是什么？
▇▇. 这个前置能力我**有数据能验证**吗？
▇▇. 不能验证 → 只准写成"待验证的假设"，进待复核队列，**不许写进机会清单当成可执行动作**。

**已沉淀**：R-532（两个池子分开算，只有交集才是可转化名单）+ R-534（上层通用规则）。

## E-14 把一种打法当成通用杠杆，套给了一个分层

**发生**（2026-09-13）：我在生态盘面写了机会⑤「腰部靠短直联动跃迁」，理由是腰部是唯一掉队档、短直已超额 ▇▇。她指出：**「腰部不一定能靠短直联动跃迁，短直是有电商能力的达人主要的推售形式」**。

**错在哪**：我用「哪一档掉队」推出「给这一档上什么打法」，中间少了一句**这个打法要什么前置能力**。短直的前置是达人会带货、有直播场，这件事和机构在哪一档**完全无关**。腰部里可能一个带货达人都没有。

**更深一层**：我把**分层（结果标签）**当成了**能力标签**在用。分层只告诉我这家机构收入落在哪个区间，不告诉我它擅长什么。

**防复发**：任何"给 X 档机构上 Y 打法"的句子，写出来之前先填这张表——
「Y 要的前置能力是 ___ ；这家机构有没有，我用 ___ 字段能查到」。**填不满就不许写成建议**，改成问题去问她或去查数据。

**已沉淀**：R-533（短直是能力杠杆不是分层杠杆）+ R-534（分层是结果标签，不是能力标签）。

## E-18 顶栏多加一个角标，窄屏整页横向溢出 21px；CSS 变量写错还静默失效

**发生**（2026-09-13）：反馈按钮加上「n/▇▇」计数后，390px 宽度下顶栏右侧组从 354px 涨到 375px，`scrollWidth - innerWidth = ▇▇`。同一轮里 `plain.css` 写了 ▇▇ 处 `var(--gap)`，而项目主题里根本没有这个变量（应为 `--signal`），删除按钮的悬浮变色一直没生效，控制台也不报错。

## E-43 · 把“补充配图”做成“替换原内容”——增量要求被误读成替换

## E-44 · 把“BI 任务已启用”当成“AIME cron 已打通”或“当日任务已跑成”
- **犯错日**：2026-10-16。
- **场景**：PRM/BI 返回任务 `▇▇` 已启用、每天 10:00（UTC+▇▇）运行；但同一时间 `aime trigger list` 与 cronjob workflow 模板仍为空，`trigger create --help` 也没有 cron 参数。
- **错在哪**：把一个系统给出的任务状态，扩大成另一个系统的能力证明；又差一点把“已启用”写成“每天都已成功刷新”。
- **后果**：如果某日没有真实取数回执，页面仍显示“已启用”，会掩盖底表未刷新、任务失败或权限过期，用户看到的就可能是旧数。
- **修法（已落地）**：记录任务 ID / 时间 / 接收人，但验收只认三件事：当日真实运行回执、数据实际截止、线上页面更新；任一缺失就写“本日未跑成”并手动补刷。
- **动手前自检**：我手上的证据是“配置存在”，还是“这一次真的执行成功”？二者不能互换。
